# 在真实企业页面录制自动填写

这次不是本地样表。动图来自面壁智能官网“语言大模型算法研究员”的真实申请页，原网页正常加载后，使用项目生产 BrowserController 和飞书原生执行器填写。没有重建企业网站，没有把静态截图拼成填写过程，也没有倍速或手动推进动画。

## 录像里实际完成了什么

- 姓名、邮箱：2项自动填写并核实。
- 两段教育、两段实习、两个项目：32个字段自动填写，5次自动新增经历。学历、年月、职位、项目角色、描述和两个链接均在其中。
- 执行后独立读取6个经历组，32个实际值与虚构履历逐项相符；基本资料及申请选项又通过原生辅助树复核。
- 推荐方式“无”、意向城市“北京”和“没有工作经历”在录像前先选好，不能算入34项自动填写。
- 网站绑定的手机号是只读项，保持原样；视频中已遮挡。其他填写内容是虚构资料。附件没有上传，最终提交没有点击。

这说明本次具体页面的业务信息填入和读回成功，不表示企业已保存、验证或接收申请。录制阶段拦截了全部新网页请求，包括151次被拦请求；不能把它们全部称为“提交请求”，也没有逐载荷检查原来已经建立的连接。

## 为什么录制器最初显示还有待处理

自动审计保守地报了4项：同组已经选择“无”时未选择的“内推”，以及已经选中北京、两所学校后仍为空的菜单内部搜索框。之后直接读取真实页面的原生辅助树，核实这些选择已经存在。原始的未通过报告保持不动，现场复核单独记录；没有把它们加入模型或基准测试的成功率。

本次没有持续记录每次瞬时值变化，不能据此宣称严格全过程无误写。没有真人配对基线，也不根据这段31.6秒视频计算人工提速倍数。视频时间还包含执行等待与结束停留，不包含登录、预先选择设置和后续人工复核。

## 录制与隐私

入口是 `scripts/record-real-form.mjs`，会把当前已提交生产源码冻结在独立目录，避免其它任务的未提交改动混入。使用者须在独立窗口用已有账号手动登录。登录时不录像；检测到已有联系人或经历资料会停止，不覆盖真实履历。

原始帧只保存在被Git忽略的本机目录中，可能含网站显示的绑定手机，不能直接分享。发布版先遮挡手机号，再逐帧解码：316帧经过本地OCR检查，并人工检查开头、运动和结束画面。只有脱敏后的GIF进入仓库，原图、Cookie、账号、验证码与私人路径不上传。

```sh
node scripts/record-real-form.mjs --output=.backups/real-recording
```

这条命令只打开独立录制器；登录、页面确认和“开始录制”仍由使用者控制。企业页面可能变化，本次录像不是跨站覆盖或未来每次都能成功的保证。
