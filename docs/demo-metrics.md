# Demo 指标：每次到底填了什么、花了多少

2026-10-19。模型为百炼北京 qwen-flash，人物资料全部虚构。把完整履历演示和普通字段回归分开，避免把7秒填好联系字段说成7秒完成所有网申。

## 更接近“填一份简历”的完整演示

真实面壁网申的单次录制：两段教育、两段实习、两个项目，共34个指定字段读回一致；12次真实API请求、11272 token。按实际输入7915、缓存输入2112、输出1245计算，费用估算 **0.00312元**；全部输入按无缓存计，约 **0.00337元**。可以对外说“这次完整履历演示约1.1万token、约0.003—0.004元模型费”。

原速连续录像约106.8秒，包含模型等待和人工选项操作，不是正式纯自动耗时基准；首页19秒动图是4倍速预览，不能写成19秒完成。指定34项一致也不能写成整张申请100%可提交：选项有人工准备，附件/声明和服务器接受未验证。只是一站一次展示，不代表跨企业整表成功率。见[原速演示与边界](model-workspace-demo.md)。

## 跨20家公司的后台Agent回归

只评普通草稿：读取确认资料→观察网页→模型决定映射并执行→模型调用最终读回。固定gold主要是姓名、邮箱、电话，复杂重复履历不属于这个20家公司分母。

| 并发 | 严格任务完成 | 20家整组耗时 | 单任务P50/P95 | 真实API / token |
|---|---:|---:|---:|---:|
| 1 | 19/20（95%） | 171.72秒 | 7.71/9.63秒 | 100 / 163855 |
| 3 | 19/20（95%） | 69.01秒 | 7.27/11.23秒 | 101 / 167673 |
| 5 | 18/20（90%） | 48.68秒 | 7.91/12.30秒 | 95 / 155914 |

60次计划任务中59次进入实际模型，平均 **8262 token/次**，按测到的缓存比例估算 **0.001041元/次**，完全不计缓存优惠约 **0.001585元/次**。可概括成“同规模普通草稿任务约8000 token、约0.001—0.002元、单任务通常7—12秒”。这不是整份简历的平均成本或耗时。

严格任务完成56/60=93.3%，三个并发组分别95%/95%/90%。原评分中的3个法律全名保守标记和1个模型开始前的加载/读取失败仍计失败，不改gold。固定联系字段147/150=98.0%正确，另3项未观察；已观察的147项值均与gold一致。这只能说明这批固定联系字段，不能称整表准确率100%。未知资料和未适配字段不纳入这些联系字段分母。

条件姓名3/3保持空白、冲突字段1/1保持空白，预算耗尽0；缺资料不编答案，显示需补充的字段。额外5家补测单列，不回填主分。[详细方法与原始判据](background-agent-conditional.md) · [逐站交互报告](background-agent-conditional.html) · [实际模型/工具轨迹](background-agent-conditional-trajectory.html)。

## 费用怎么算

官方页面在核验时给出的北京实时推理单价：输入≤128K时，非缓存输入0.15元/百万token、隐式缓存命中输入0.03元/百万、输出1.5元/百万。公式为 `(非缓存输入×0.15 + 缓存输入×0.03 + 输出×1.5) / 1000000`。Pi usage的input已经扣掉cacheRead，不能重复把缓存算进非缓存输入。本轮无cacheWrite，全部请求在该输入阶梯内，没有使用Batch折扣。

这是按[阿里云官方单价](https://help.aliyun.com/zh/model-studio/qwen-flash)和实际usage计算的估算，**没有读取账单**，不含免费额度、促销、其它服务商价格、登录/网络/人力成本。价格会变化；token总量不能单独乘某一个输入单价，也不能把SDK占位0元当真实免费。
