# OfferFlash：岗位发现与人岗匹配测评调研

核验日期：2026-10-19。本文为测评协议建议与源码审阅；没有下载真实简历数据、读取用户库或调用付费模型，没有产生人工标注金标准或模型效果结论。

## 推荐采用的方案

本项目应同时测两件事：**在明确范围内有没有把岗位找全**，以及**找到以后是否把适合这份简历的岗位排在前面**。采集 HTTP 200、规则分数高、模型说“匹配”都不能代替这两项证据。

第一版采用原创虚构履历和固定候选库，先把评分器、负例、失败记录和报告做成可复现实验；这一部分叫 `synthetic-controlled`。真实官网岗位单独做 `official-snapshot`：留来源与抓取时间，标签保持待评阅。只有独立评阅和裁决后的标签才能进入 `human-adjudicated` 主结果。不能把生成者兼任的自评叫人工 gold，也不能用当前 `matchJob` 的分数生成“标准答案”。

## 本地匹配实现的实际能力

审阅 `packages/domain/src/matching.ts`：`matchJob(profile, job, now)` 是确定性规则。它用已确认默认教育替换教育输入；按招聘类型、城市、方向别名与已确认技能计分；学历、毕业届数/月份窗口、截止日做显式排除；例外、未知信息放入 `concerns`。输出 `score` 是规则排序分，不是 offer 概率，也不是人工适合度。

源码里能看到需要专门测的点：

- 方向/技能主要通过词项与少量别名命中；论文/项目中可迁移能力、同名异义及“并不要求某技能”等语义不能只凭命中判正确。
- 学历优先与强制要求、毕业月份窗口与届数、实习时间与毕业时间已经做区分；应保留反例证明，而非只放简单正例。
- 城市可能是明确不合适、全国/多地或未知；三种结果必须分开。大陆默认限制还在发现流程，不能只测 `matchJob` 就说海外已排除。
- 发布日期、截止日期缺失会留下待核对；`review` 可能只有日期未知，也可能存在关键资格未知，评测不能一律算不合适或一律算通过。
- 当前规则不是使用向量检索的 RAG 排序器。增加数据库或向量索引本身不等于完成匹配质量评测。

## 冻结建议：标签与未知信息

一个样本是 `(profileVersion, jobSnapshotId, asOf)`。必须分别保存 `semanticRelevance` 和 `eligibility`，并保留判断证据出处。这里的标签标准为项目自定义协议，非外部基准官方规则。

语义匹配 `semanticRelevance` 取 0–3：

| 分数 | 含义 |
| --- | --- |
| 3 | 核心工作与目标方向一致，履历中有具体项目/实习/论文证据覆盖主要能力；不能只因职位含 AI 就给 3。 |
| 2 | 方向相符，有关键能力证据或明确可迁移经历，但存在次要技能差距；值得进入候选。 |
| 1 | 相邻方向或只有笼统关键词重叠，核心任务所需证据不足；作为探索项。 |
| 0 | 核心任务不相关、目标方向相悖，或无相关能力依据。 |
| null | 未评阅、原文不足或存在无法裁决的语义歧义；不当成 0。 |

资格 `eligibility` 取 `eligible / ineligible / unknown`。每个维度再单独记 `pass / violation / unknown`，避免“知道它在国外”被误读为“已经审核了所有学历/届数要求”。维度至少含：大陆范围、意向城市、毕业届数/月窗、最低学历、招聘类型、截止时间、来源时效、官方来源。

- 只在网站明确强制、履历明确且冲突时标 `violation`；“硕士优先”不直接排除本科，“2027届优先”不当成硬性届数。
- 香港教育经历不决定工作地区；“国内”默认大陆，港澳台单独标记，海外需明确偏好。
- 未给毕业月、网站只写“应届”、日期含例外/无法解析，均标 `unknown`。未知资格不能成为“肯定满足”的证据，也不应自动标失败。
- 职责匹配但明确超过截止日期，语义仍可为 3，资格为 `ineligible`；展示排序可过滤，但不能改语义 gold 来掩盖过滤效果。
- 若一个已知硬约束失败，整体 `ineligible`；没有失败但有关键未知则 `unknown`；只有所要求维度证据充足且满足才 `eligible`。
- 完整、待评阅与缺资料样本分别统计。人工标注时先隐藏模型名和排序，至少两名独立评阅，分歧裁决；记录版本与一致率。用户睡觉期间不能虚构完成了这一环节。

## 核心指标与分母

排序指标遵循信息检索常见定义：[Stanford IR 教材](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)说明 Precision/Recall 与分级相关性；[scikit-learn nDCG 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)提供标准化增益与 tie 处理背景。以下具体阈值、增益与缺标规则由 OfferFlash 冻结，不声称与所有库默认完全相同。

- 主排序：nDCG@5/10，增益固定 `2^grade - 1`，折扣 `log2(rank+1)`。先按每份履历算，再宏平均；明确同分时使用固定岗位 ID 排序。全候选库有未知 grade 时不出主 nDCG，另报标签覆盖率。
- 有用推荐：Precision@5/10 和 Recall@10/20，以 grade ≥ 2 为 relevant。Precision 分母固定 K；少返回的空位算零贡献。Recall 分母是该冻结库所有 relevant 岗位，不是“本次返回的匹配岗位”；未知 gold 使完整 Recall 不可算。
- 首次命中：MRR@10，grade ≥ 2。已知首命中之前若有未评阅结果，MRR 未知；后面的未知不改变已确定的首命中。
- 资格：Top-K 已审资格项中的违例数 / 已审资格项数，另报已审数/返回数；每个约束维度分别用该维度已审数做分母。零已审显示未知，不显示 0% 违例。
- 标签覆盖：完整 corpus 已评数/总数、Top-K 已评数/实际返回数、未知资格数。没有 relevant 的负控履历单列，Recall/nDCG 不纳入正常宏平均；仍保留误推荐数。

纯评分器已放 `packages/evaluation/src/ranking-scoring.ts`；不依赖生产匹配器，不读取文件/网络/数据库，不生成 qrels。它拒绝重复 rank/qrel 和非法 K，缺标签保持未知；返回 value、numerator、denominator 和原因。调用者负责固定候选库、模型预算与报告样本类型。

## 采集全面性与实时性：不能用“全网Recall”冒充

独立维护企业/来源目录与时间切片。可证明范围是“固定企业 X、渠道 Y、地区 Z、截至 T 的官网公开列表”，不能把几家来源上升为国内全覆盖。

1. 列表覆盖率：同一时间窗口独立枚举得到的官网岗位 ID 集合作分母；采集器得到的唯一 ID 交集作分子。来源不能完整枚举时标 `partial`，不报全站 Recall。可另建受控分页服务，精确知道所有页/岗位，测完整性但明确叫受控样本。
2. 字段覆盖率与正确率：JD 职责、要求、地点、类型、日期、原始 URL 逐字段核验。HTTP 成功率与可用完整 JD 率分开。多源同岗位去重后算唯一岗位，别把重复计覆盖。
3. 新鲜度：只有独立知道岗位首次公开时间才能算 discovery lag；首次采到不是发布时间。否则报告 `lastVerifiedAt` 距现在多久及轮询间隔，不补造“实时延迟”。
4. 招聘关闭：预算截断、超时、返回空页都不能自动标关闭。只有明确关闭证据或完整快照的既定多轮消失规则才能转状态；采集失败保留历史岗位。
5. 分层结果：官网/转载、校招/实习/社招、AI-Agent/算法-RL/其他、明确资格/未知资格、精确词/语义迁移/否定词分别展示。固定冻结时间使截止日边界可复测。

## 可执行实验顺序

先在原创受控数据冻结标签与脚本：`matchJob` 当前规则、独立 BM25、混合召回/后续 embedding、模型 rerank 共用一个候选库与 K。embedding 与 rerank 若接入，只改一项、预算相同；召回候选集变化与固定候选重排分轨报告。生产规则生成的 reasons 不能作为独立正确性证据。

随后拉官方公开岗位快照，记录不可访问、partial、原文缺失和过期情况；评分时优先保留未评阅状态，可生成盲评表供用户醒后核对。只有人工裁决足够覆盖后发布真实岗位匹配得分。未完成标注不能用 LLM judge 的高分补上；模型 judge 可做辅助，必须独立于被测模型并在人工子集校准，单列为 `model-assisted`。

RAG 的 Hit@K/Recall@K 应针对“哪个已确认履历事实能支持这个问题”或“哪个 JD 片段能支持岗位判断”，提供真实证据 ID；拿到公司名称但没拿到毕业月要求不算命中完整资格。检索指标、最终推荐和实际填表正确率各算各的，避免上游检索一次命中就宣称端到端成功。
