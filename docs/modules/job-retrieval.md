# 全库岗位检索

生产入口：`apps/desktop/job-matching-service.ts`。默认范围为当前全部非demo岗位；显式来源ID可覆盖至10000条，不再取queryJobs第一页作为模型全部范围。超过单轮索引容量明确报错，不悄悄截取前20条。候选范围全量内容指纹和资料版本绑定结果；新增/修改/删除岗位会使全库结果失效。

`packages/agent/src/job-retrieval.ts`：

- 使用明确临时求职方向或已保存targetRoles。只投影已确认当前修订的职业事实，排除姓名/联系方式字段、原始简历和来源备注；没有方向提示补充。临时方向不改变持久资料和硬条件偏好。
- 先用现有matchJob和明确地区证据排除已识别冲突，未知保留复核。该步仍是有局限的解析器，不等于完整资格证明。
- 每个库内岗位都进入范围检查；全部未被明确排除的岗位参与BM25评分、语义编码与排序，不先裁掉旧规则20条。中文二元词与英文技术词、固定同义词表；标题加权，查询优先求职方向与真实项目。否定/未声明经历不作为正面关键词。
- 真实text-embedding-v4、512维、余弦相似度；与词法排序用等权RRF、常数60合并，固定取20条，再交给原普通模型做0–5条重排。原提示与评分不改，不将检索分数当录用概率。
- 向量编码每条最多6000字符，较长JD明确统计截断；词法检索仍使用全部存储正文。不是声称编码覆盖所有长JD细节。索引上限10000岗位/2400万正文字符，不通过任意输入URL抓网页。

`job-embedding.ts` 是固定百炼北京只读embeddings端点，10文本一批、并发2、20秒请求、无重试，验证维度/索引/有限非零向量。公有JD和职业查询向量只在进程内按内容hash缓存，配置关闭即清；不持久化查询、密钥或向量，不访问Keychain，不把密钥送renderer。主进程复用现有临时模型配置，仅百炼北京qwen-flash支持此入口。

语义失败：正式比较拒绝降级；App明确标“全库关键词”，不宣称语义成功，未完成请求用量显示未知。取消要等待实际在途请求结束，资料/模型配置仍受忙锁，主服务120秒总上限。无浏览器/投递写权限。

申请空间的方向输入和按钮、发现后再匹配、聊天匹配全部走同一服务。聊天获得宿主实际选出的完整岗位记录，允许来自旧第一页以外的结果；列表数量和编号沿实际返回顺序。明确离线请求不执行语义/模型网络。

真实岗位数据、先锁GT/原评分及结果见[本轮报告](../release/real-job-retrieval.md)。这次没有证明混合推荐相关率提升，也没有完成全网覆盖；工程上已消除“只能看到旧前20条”的限制。
