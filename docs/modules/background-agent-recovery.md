# 后台 Agent 写后恢复与最终核对

2026-10-19。沿用原真实 API 20 家回归面板，评分、gold、模型、主系统提示与每任务 6 次模型/10 次工具/90 秒预算保持不变。原始 RC1 与本轮修复独立归档，不修改历史。

## 已证实的故障与修复范围

原 RC1 单并发的 9 个 `value-not-retained` 任务，最终联系字段值均匹配。原始只读观察显示：Greenhouse 电话填入后可见字段数量、顺序、标签、身份、类型、选项和其它元数据相同，但电话及后续控件索引变动。旧执行器要求写后整个快照仅有目标值变化，因此停止。历史记录未保存完整隐藏控件读数，不能凭旧截图宣称所有保护状态也相同；本轮隔离审计额外保存完整后台原始读数。

`packages/browser/src/background-executor.ts` 新增 `reconcileBackgroundReindex`，仅处理上述有界情形：

- 与预期写后状态比较，只有 index 可变，顺序和所有其它字段属性、值必须相同；完整 protected 快照必须相同。
- 移动字段必须有显式 DOM id 或 name，且 identity 唯一；未知或歧义不按标签/顺序猜目标。
- 经过原有 80ms 读回及 180ms 稳定核对，变化后的整个快照必须稳定。URL、页面代次、资料版本、取消和 native validity 继续独立检查。
- 下一字段从原计划身份重新找到唯一当前控件；写入前仍做完整即时快照比较，网页固定 setter 内仍原子检查一次。
- 新增/删除字段、值丢失或非目标值变化、选项变化、身份变化、声明/附件变化，都不能借这个路径继续；部分或未知写入不盲目重试。

这不是全面容忍 React 重建，也不是把已失败任务改成成功；只有执行器得到完整新核实证据才增加 verified。

## 最终核对的流程检查

`packages/agent/src/background-form-agent.ts` 在填写回执明确返回 `nextRequiredTool: read_fill_status`。模型若以文字结束而没有调用核对工具，在请求尚余至少两次且任务未取消时，最多向同一个 Pi 会话追加一次只读提醒。该阶段其它工具被宿主拒绝，实际模型必须自己调用读回；不增加 API、工具或时间预算，也不合成 SDK tool_result。

核对工具成功读回之后才增加 statusReads；重新检查页面/资料代次，并逐项检查实际写入的目标。若目标值或身份不再对应，保留失败，不因文字声称完成而放行。审计记录保存真实连续 SDK 事件、提醒次数和模型请求。

## 验证和边界

专项测试覆盖稳定编号变化后继续填写，以及非目标值、选项、身份、保护状态、歧义、字段增加时停止；SDK 脚本合约证明漏读会触发真实工具调用。这些脚本模型测试不计付费模型或真实官网任务成绩。

真实两站预检使用 Portcast 与 Verantos、相同虚构资料和 API，10 请求、14747 token，2/2 完成；预检不并入正式分母。正式复测独立见 `docs/background-agent-recovery-validation.json` 和 `docs/release/background-agent-recovery.md`。没有更改法律全名的保守负向标记；没有上传或提交申请，没有读取普通私库、账号或钥匙串。
