# 条件姓名题与模型错误重试修复

2026-10-19。沿用后台Pi Agent唯一会话内核、固定四工具；前台聊天仍为11个工具和3个项目自有Skill。本轮不加载第三方Skill或外部提示词，不读普通私库、真实简历、Cookie或系统Keychain，不提交或上传申请。

## 证明的问题

v0.12.1真实回归中，Cloudflare的 `Legal Name (if different than above)` 被复用了普通完整姓名，网站条件是否成立却没有已确认事实。ShieldAI单并发会话中，模型给同一个fieldId分配school/major等不同键；宿主以 `DUPLICATE_MODEL_MAPPING` 拒绝整批、消费观察ID，模型再次提交相同映射触发 `FRESH_UNUSED_OBSERVATION_REQUIRED`，又重新观察后重复错误，6次请求耗尽，连普通联系字段都没有执行。原始会话、失败、评分和源码均保留在忽略备份。

## 姓名不猜填

`packages/forms/src/field-review.ts` 只识别需要额外事实的条件/替代姓名问题，如“如与上述不同”“如有”“曾用名”“previous/other names”。`matchFields`和模型映射验证都复用这个审阅判断；不会从普通fullName推断条件成立或曾用姓名。已有网页值保留，缺资料项列出字段名，提示用户补充确认或手动处理。提示不会写入个人资料，也不会把草稿自动确认。

无附加条件的完整/法律姓名仍按原普通姓名事实核对，不因基准负向标记保守就封禁。原gold对ShieldAI法律全名的标记保持不变，因此它仍可能计失败；不能通过按公司名/题目白名单跳过来刷分。

## 错误不拖垮其它字段

`packages/agent/src/background-form-agent.ts` 在写入前统计模型映射的fieldId：某字段重复或冲突，则该组全部拒绝并留空，不取第一个、最后一个，也不挑“看起来正确”的键。其它模型明确提出的映射分别通过编号、语义、类型、确认资料和页面守卫后才执行；没有模型映射的字段仍无规则回退。

未知编号、类型和明确用途冲突使用有类型的验证错误，仅拒绝该项并返回结构化原因。意外程序错误仍抛出，不将它当成可忽略的缺资料。缺少已确认值也单独拒绝；资料不从网页、工具自由文本或模型推断。

成功执行后锁成只读阶段，模型必须调用 `read_fill_status`；读回之前不能重新观察或再次填写。最终核对只有真实成功读回才计数，早于填写的读回不算。写入后的上下文/代次/原值/保护控件守卫、一次观察消费和不盲重试规则保持。

## 用户提醒与证据

工具返回 `needsUserInput`，每项有fieldId、字段标签、required和固定原因。宿主最终message列出待补充/确认的字段；现有队列将result.message保存到对应任务，QueuePanel显示这个message。最多摘要3项并给出总数；不会把任意网页标签当指令或给提醒赋写入权限。完整审阅原因留在只读状态工具和私有任务证据中，不包含个人值。
